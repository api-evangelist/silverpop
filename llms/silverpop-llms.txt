## What an agent needs to know first

- **There is no single base URL.** The host embeds a region and a pod number, one per
  tenant: `https://api-campaign-{region}-{pod}.goacoustic.com` — us-1, us-5, eu-1 and so
  on. The value comes from the Campaign UI's Org Admin section. There is no discovery
  endpoint. Hardcoding us-1 addresses the wrong tenant estate.
- **There are two APIs behind that host.** `/XMLAPI` is a single POST endpoint where the
  operation is the root XML element (about 60 documented operations). `/rest` is a later,
  narrower JSON surface (11 resources). They share auth and nothing else — different
  payloads, different error shapes.
- **The binding limit is concurrency, not rate.** 10 concurrent authenticated requests per
  ORGANIZATION. The 11th is rejected outright, not queued. No rate-limit response headers
  exist on the API; do not look for `X-RateLimit-*`.
- **There is no scope model.** A refresh token inherits the full Campaign permissions of
  the human user it is bound to. An agent holding one can call PurgeData and
  ScheduleMailing — erase data and send email to real people.
- **There is no OpenAPI.** The only machine-readable service description is Swagger 1.1,
  served live from the API host at `/restdoc/<resource>`.

## Authentication

OAuth 2.0, refresh_token grant only.

- `POST https://api-campaign-{region}-{pod}.goacoustic.com/oauth/token`
- Body: `grant_type=refresh_token`, `client_id`, `client_secret`, `refresh_token`
- Returns an `access_token` with `expires_in` of 4 hours. Present it as
  `Authorization: Bearer <access_token>`.
- `client_id`/`client_secret` are minted per APPLICATION in Organization Settings →
  Application Account Access. The `refresh_token` is minted per (application, user) pair
  and is EMAILED to the requesting user and the principal org admin — it never comes back
  from an API call.
- Refresh tokens do not expire; they are revoked from the UI.
- Reuse the access token across calls. The provider recommends minting a new one every 3
  hours, inside the 4-hour window.
- Legacy JSESSIONID session auth still works but is deprecated in prose, capped at 20
  active sessions per org, and has no retirement date.

Docs: https://developer.goacoustic.com/acoustic-campaign/reference/getting-started-with-oauth

## Errors

Two catalogues, no problem+json.

- XML API: fault envelope carrying a numeric `errorid` and a human `Fault String`. 116
  documented codes. Notable: 50 server error / bad request, 51 invalid XML, 52 missing XML
  parameter, 121 no EMAIL provided, 122 recipient already exists, 123 recipient does not
  exist.
- REST API: HTTP status with a general-errors / field-errors split. 400 malformed, 404
  unknown database or contact, 422 per-column validation, 500 internal — including a 500
  when the submitted email is on the system blocked list, which is a policy outcome
  returned as a server error.
- No 429 and no Retry-After anywhere in the reference.

Full catalogue: errors/silverpop-problem-types.yml
Docs: https://developer.goacoustic.com/acoustic-campaign/reference/error-codes

## Retries and bulk reads

- No idempotency key. A retried create is distinguishable from a first create only by
  reading error 122 back off the fault envelope.
- Bulk retrieval is asynchronous, not paginated. ExportList, ExportTable,
  RawRecipientDataExport and WebTrackingDataExport return a job id; poll GetJobStatus,
  then DeleteJob. There is no cursor or offset convention.
